# 复现步骤

从一台干净机器到跑通的七步。每一步都写了**怎么验证**，别跳着做。

**前提**

- Windows 10/11，能安装微软商店的 MSIX 应用
- 能访问 `api.deepseek.com` 的网络
- 一个 DeepSeek API Key
- 官方 ChatGPT Desktop（包名 `OpenAI.Codex`）已安装并能正常使用

---

## 第 1 步：让官方客户端先跑起来

用你自己的账号正常打开客户端，聊一句话。

这一步不能省：客户端会在这时候下载运行时（`%LOCALAPPDATA%\OpenAI\Codex\bin\<哈希>\codex.exe`、`runtimes\cua_node\<哈希>\`），并生成 `%USERPROFILE%\.codex\` 里的插件缓存、`.system` 技能、`bundled-marketplaces`。后面要复制的就是这些。

**验证**：`%USERPROFILE%\.codex\config.toml` 存在，且 `%LOCALAPPDATA%\OpenAI\Codex\bin` 下有内容。

## 第 2 步：复制出 DeepSeek 的家目录

```powershell
Copy-Item "$env:USERPROFILE\.codex" "$env:USERPROFILE\.codex-deepseek" -Recurse
```

只复制 `config.toml`、`models.json`、`rules\`、`skills\` 其实就够了。`.sandbox*`、`.tmp`、`*.sqlite`、`sessions` 让应用自己重建更干净——它们带着旧机器的绝对路径和会话数据。

**验证**：`.codex-deepseek\config.toml` 存在。

## 第 3 步：写配置

用 `config\config.deepseek.template.toml` 覆盖 `.codex-deepseek\config.toml`，改两处：

- `<你的用户名>` → 你的实际用户名
- `<YOUR_DEEPSEEK_API_KEY>` → 你的 Key

注意 `sandbox` 一项：本仓库模板默认给的是 `unelevated`。用 `elevated` 时本机出现过每条命令都失败的情况，原因见 `实现细节.md` 第 5.1 节。

**验证**：文件里不再有 `<...>` 占位符。

## 第 4 步：放模型目录文件

把你自己造的 `models.json` 放到 `.codex-deepseek\models.json`，确认 `config.toml` 里的 `model_catalog_json` 指向它。

文件结构见 `实现细节.md` 第 3 节。**这一步是本套里最需要自己动手的地方**：仓库里没有这个文件，因为里面包含官方的系统提示词原文。

**验证**：JSON 能被解析，且 `models` 数组里至少有一条的 `visibility` 是 `"list"`。

## 第 5 步：装启动器

把 `launcher\` 下三个脚本复制到 `%USERPROFILE%` 根目录（**必须放这里**，快捷方式按绝对路径调用它们）：

```powershell
Copy-Item .\launcher\*.ps1 $env:USERPROFILE
```

然后在桌面建两个快捷方式：

| 快捷方式 | 目标 |
| --- | --- |
| DeepSeek Codex | `powershell.exe -NoProfile -ExecutionPolicy Bypass -WindowStyle Hidden -File "%USERPROFILE%\Start-DeepSeek-Codex.ps1"` |
| 关闭 DeepSeek Codex | `powershell.exe -WindowStyle Hidden -NoProfile -ExecutionPolicy Bypass -File "%USERPROFILE%\Stop-DeepSeek-Codex.ps1"` |

启动器里的 `Andy.DeepSeekCodex` 和窗口标题可以改成你自己的标识，改完两个实例的任务栏身份不会撞。

**验证**：`powershell.exe -NoProfile -Command "& { $null = [System.Management.Automation.Language.Parser]::ParseFile('$env:USERPROFILE\Start-DeepSeek-Codex.ps1', [ref]$null, [ref]$e); $e.Count }"` 返回 0（语法无误）。

## 第 6 步：启动并验证

双击「DeepSeek Codex」。

**验证清单**

- 模型下拉框里能看到你定义的 DeepSeek 模型。
- 问一句话能正常回复。
- 官方实例仍然开着，两个窗口在任务栏是**两个独立图标**。
- 用「关闭 DeepSeek Codex」退出后，官方实例不受影响，且 `Get-Process ChatGPT` 里不带 `deepseek` 标记的进程都还在。

## 第 7 步：验证沙箱

随便让 DeepSeek 实例读一个文件。

**验证**：命令能直接跑通。如果出现 `helper_sandbox_lock_failed`，说明还在用提权沙箱，回到第 3 步改 `sandbox` 设置，或按 `实现细节.md` 5.1 节修目录权限。

---

## 卸载 / 回滚

这套东西没有安装器，所以卸载就是删东西。**先关掉两个实例，再动手**：

| 要删的 | 说明 |
| --- | --- |
| `%USERPROFILE%\.codex-deepseek` | 整个目录，这是 DeepSeek 实例的全部数据 |
| `%LOCALAPPDATA%\CodexProfiles\deepseek` | 浏览器数据，登录态与缓存 |
| `%USERPROFILE%\Start-DeepSeek-Codex.ps1` 等三个脚本 | 复制出去的启动器 |
| 桌面两个快捷方式 | — |
| 本机账户 `CodexSandboxOffline` / `CodexSandboxOnline` | 只有确定不再用提权沙箱时才删 |

官方实例（`%USERPROFILE%\.codex`）不受影响，不需要动。

## 还没被验证的部分

本文是按一台已经跑通的机器**反推**出来的流程，作者没有在干净机器上完整走过一遍。已知的两个不确定点：

1. `.codex` → `.codex-deepseek` 的最小复制集合（第 2 步说的"只复制四个就够"没有逐一验证）。
2. 自己造的 `models.json` 是否够用（第 4 步）。

如果你跑通了或者卡住了，欢迎开 issue 说一声，我把结论补进来。
