# 从使用 AI 到搭一套自己的双 Agent 环境

> 面向：普通读者、以及半年后忘了自己干过什么的我。
> 技术细节在 `实现细节.md` 和仓库 README，这一篇讲的是为什么做、怎么走到这里的。

---

## 起点

最开始用 AI，我和大多数人一样：提问，拿到答案，关掉窗口。

这种用法对付单点问题很好用。但真拿它做长期项目，问题就来了——上下文会丢，进度没地方记，计划和执行混在一段对话里。聊到第一百轮的时候，它不知道第一百轮之前发生过什么，我也不知道自己上周让它改过哪。

真正让我决定动手的是一个更朴素的想法：**如果 AI 是一个长期协作者，它就应该有自己的工作位、自己的记忆、自己的职责范围**，而不是一个每次都从零开始的聊天窗口。

## 最初的设想

第一个目标不是造框架，而是解决一个实际问题：怎么让不同的 AI 各干各擅长的事。

用了几个月之后，分工其实很清楚：

- 推理强的模型擅长思考、规划、分析、审查；
- 执行侧的模型擅长改代码、动文件、跑命令、快速迭代。

于是有了最初的架构：

```
        人
         │
   GPT Planner  ──→  计划
         │
 DeepSeek Executor ──→ 代码 / 文件 / 测试
         │
   GPT Reviewer ──→ 审查与下一步
```

想清楚了这一层，我以为剩下的是写脚本。结果真正卡住我的是另一件事。

## 最大的问题：让两个 AI 真的独立

一开始我以为装两个客户端就行。实际不是。

一个现代 AI 客户端不是"一个 exe"，它是这些东西的总和：用户身份、登录状态、本地数据库、会话历史、插件、模型配置、工作目录、缓存，以及 Windows 层面的应用身份。直接复制一份会出现：

- 两边共用同一个配置目录，改一边会影响另一边；
- 会话、缓存互相污染；
- 桌面上两个窗口被 Windows 当成同一个程序，任务栏图标合并成一个，根本分不清哪个是哪个。

所以我花最多时间的不是"接入 DeepSeek"，而是**怎么在 Windows 上造出两个互不相干的应用身份**。

## 最后做出来的东西

隔离分三层，缺一层都不干净：

**第一层，配置隔离。** 两个实例用不同的 `CODEX_HOME`：

```
官方 GPT 实例      %USERPROFILE%\.codex
DeepSeek 实例      %USERPROFILE%\.codex-deepseek
```

配置、会话、技能、插件全在各自的目录里。

**第二层，数据隔离。** 客户端底下还有一层 Chromium 的浏览器数据，用不同的 `--user-data-dir` 分开，登录态和缓存也不会串。

**第三层，身份隔离。** 这一层最难，也最有意思。Windows 判断"这是不是同一个程序"靠的是窗口的 `AppUserModelID`，而它默认给两个实例同一个值。解决办法是启动之后用 Win32 API 把第二个窗口的 `AppUserModelID` 改掉：

```csharp
SHGetPropertyStoreForWindow(hwnd, IID_IPropertyStore, out store);
// 写 PKEY_AppUserModel_ID
store.SetValue(ref key, ref value);
store.Commit();
```

代码不长，但从"知道要这么做"到"它真的生效"中间踩的坑不少：设置身份必须在主窗口出现之后，而启动进程不会等你；`Add-Type` 在一个会话里只能注册一次。

最直观的结果是任务栏：从合并成一个图标，变成两个独立入口，一个叫 ChatGPT，一个叫 DeepSeek Codex。

## 困难最大的地方不是代码

这个项目教我的第一件事：**一个应用程序不等于一个 exe 文件**。

它等于程序 + 配置 + 身份 + 数据 + 权限 + 系统接口。看起来只是"复制一个 AI 客户端"，实际牵出来的是 AppX 包结构、环境变量、用户目录管理、进程管理、Windows 应用身份、权限控制这一整套东西。

第二件事更扎心：**能跑通的配置不等于能复现的配置**。

我这套环境是自己一步步试出来的，当时那版安装脚本后来弄丢了——它写下过的痕迹还在（一份 manifest、一份备份配置），但脚本本身没了。于是出现了一个很怪的状态：环境每天正常工作，但我没法凭记忆把它在另一台机器上重新搭一遍。

这件事改变了我对"做完"的判断标准。能跑，只是做完了一半；能复现，才算做完。

## 顺手记下来的几个坑

都是真踩过的，写在这里省得下次再踩：

- 提权沙箱在有些机器上会整体失败，原因是沙箱目录的 ACL 权限不够，改不动 DACL。表现是每条命令都报错，看起来像网络问题，其实是权限问题。
- Windows PowerShell 5.1 会把没有 BOM 的 UTF-8 脚本当 ANSI 读，脚本里的中文直接把语法解析坏。
- 改了配置文件必须完全退出应用（连托盘图标一起），否则读的还是旧值。
- GitHub 的 git 端口和 API 端点是两条路，一条不通的时候另一条可能还是通的。

## 这个项目意味着什么

它不是一个"更大的聊天机器人"。

我真正想验证的是：**一个人能不能拥有一套属于自己的 AI 工作系统**——不是每次打开一个窗口问问题，而是有一个持续存在的环境，里面有负责思考的、有负责动手的、有负责挑毛病的，状态记在文件里，谁都能接手。

这个仓库只是那个系统的地基：先把两个身份分开，再谈它们怎么协作。

最后用一句我很喜欢的话收尾：

> 如果 AI 真的是未来的生产力，那为什么我们不能拥有属于自己的 AI 工作系统？
