# 实现细节

本文记录这套环境**实际是怎么工作的**，以及踩过的坑。所有结论来自对一台真实机器的只读检查（Windows 11，ChatGPT Desktop 26.908.9136.0，客户端 0.154.0）。

---

## 1. 两个实例是怎么分出来的

两个环境不是两个软件，而是**同一个 `ChatGPT.exe` 的两个进程**，靠启动时的环境变量和命令行参数区分：

| | 官方实例 | DeepSeek 实例 |
| --- | --- | --- |
| 环境变量 `CODEX_HOME` | `%USERPROFILE%\.codex` | `%USERPROFILE%\.codex-deepseek` |
| 命令行 `--user-data-dir` | 默认（`%APPDATA%\Codex\web\Codex`） | `%LOCALAPPDATA%\CodexProfiles\deepseek\web-data` |
| 任务栏 `AppUserModelID` | 默认 | 自定义（本仓库用 `Andy.DeepSeekCodex`，可改成你自己的） |
| 窗口标题 | 默认 | 「DeepSeek Codex」 |
| 模型 | 官方模型 | `deepseek-flash` |

判断哪个进程属于哪个实例，看命令行里有没有 `CodexProfiles\deepseek\web-data` 这段字符串即可。

`CODEX_HOME` 决定配置、会话、技能、插件的家目录；`--user-data-dir` 决定 Chromium 那一层的浏览器数据（登录态、缓存、侧边栏）。**两个都要换，只换一个会互相污染。**

## 2. 让 DeepSeek 真正生效的六个配置点

全在 `.codex-deepseek\config.toml` 里，缺一个都不成立：

| # | 键 | 值 | 作用 |
| --- | --- | --- | --- |
| 1 | `model` | `deepseek-flash` | 默认模型 |
| 2 | `model_provider` | `deepseek` | 指向下面的供应商块 |
| 3 | `[model_providers.deepseek]` | `base_url = "https://api.deepseek.com/"`、`wire_api = "responses"` | 走 DeepSeek 官方的 responses 接口 |
| 4 | `experimental_bearer_token` | 你的 API Key | 认证 |
| 5 | `model_catalog_json` | `.../.codex-deepseek/models.json` | **没有它，GUI 模型列表里不会出现 DeepSeek** |
| 6 | `preferred_auth_method = "apikey"` + `forced_login_method = "api"` + `cli_auth_credentials_store = "file"` | — | 绕开 ChatGPT 账号登录，直接走 API Key |

另外建议 `web_search = "disabled"`：DeepSeek 侧没有对应的官方搜索工具。

## 3. 模型目录 `models.json`

结构是 `{ "models": [ ... ] }`，每一条模型是一个大对象。两个模型条目就够：

| slug | display_name | priority | context_window |
| --- | --- | --- | --- |
| `deepseek-flash` | DeepSeek-Flash | 1 | 1048576 |
| `deepseek-v4-pro` | DeepSeek-V4-Pro | 2 | 1048576 |

除标识字段外，这些字段决定它的行为：

- `input_modalities = ["text", "image"]`、`supports_parallel_tool_calls = true`
- `apply_patch_tool_type = "freeform"`、`shell_type = "shell_command"`
- `visibility = "list"`（出现在模型下拉框里）、`priority`（排序）
- `supported_reasoning_levels`（low / high / max）、`default_reasoning_level = "high"`
- `minimal_client_version`（本机是 `0.144.0`）

### 为什么本仓库不包含这个文件

每一条模型里都带一份 `base_instructions`（约 1.8 万字符）和 `model_messages.instructions_template`，内容是**从官方客户端里拿到的系统提示词原文**。它决定了这个实例的人格、写作风格、工具使用规则。这份文字不属于这个项目，公开分发不合适，所以仓库里只描述结构。

自己造一份时的已知事实：

- 本机那份**不是**从当前官方模型缓存（`.codex\models_cache.json`）克隆来的，字段集对不上：官方条目有 `additional_speed_tiers`、`service_tiers`、`node_repl_disabled` 等，它没有；它有 `prefer_websockets`、`minimal_client_version`、`base_instructions`、`auto_compact_token_limit`，官方条目没有。字段形状对应的是更早的客户端版本。
- 因此"克隆官方条目改个名字"是否够用，**没有验证过**。改完要实际启动看模型下拉框和对话能不能用。

## 4. 任务栏身份分离（本项目的核心）

两个实例跑起来后，Windows 默认会把它们当成同一个程序，任务栏图标合并成一个。解决办法是启动后设置窗口的 `AppUserModelID`：

```csharp
// 关键调用，完整实现在 launcher/Start-DeepSeek-Codex.ps1 里
SHGetPropertyStoreForWindow(hwnd, IID_IPropertyStore, out store);   // 拿窗口的属性仓库
// 写 PKEY_AppUserModel_ID = {9F4C2855-9F79-4B39-A8D0-E1D42DE1D5F3}, 5
store.SetValue(ref key, ref value);
store.Commit();
SetWindowText(hwnd, "DeepSeek Codex");                              // 顺便改标题
```

实现要点：

- 用 `Add-Type` 内嵌 C#，不需要编译 DLL，也不需要注册表。
- `Add-Type` 在同一个 PowerShell 会话里重复执行会报错，所以启动器先判断 `if (-not ("TaskbarIdentity" -as [type]))`。
- 设置身份必须在**主窗口出现之后**，而 `Start-Process` 不等待。现做法是轮询进程列表找到带 `web-data` 标记的进程，再取它的 `MainWindowHandle`，最多等 20 秒。

## 5. 已知的坑

### 5.1 提权沙箱会整体失败（最影响体验）

`[windows] sandbox = "elevated"` 时，沙箱需要给 `.sandbox-bin` 目录设置 ACL，而在这台机器上这一步一直被拒绝：

```
helper_sandbox_lock_failed: lock sandbox bin dir ...\.sandbox-bin failed:
SetNamedSecurityInfoW sandbox dir failed: 5
```

错误会每隔一两秒重复一次，之后降级成 "read-acl-only mode"。表现是**每一条命令都失败**，改文件也要额外提权。

根因是目录权限，不是配置语法：

| 目录 | 所有者 | 当前用户权限 |
| --- | --- | --- |
| `.sandbox-bin`（出问题的） | `BUILTIN\Administrators` | 只有 `Modify`（不含 `WRITE_DAC`） |
| 旧环境同名目录（正常） | 当前用户 | `FullControl`（继承） |

`SetNamedSecurityInfoW` 需要 `WRITE_DAC`，`Modify` 不含它，所以必然返回 `ERROR_ACCESS_DENIED (5)`。

两个修法：把 `sandbox` 改成 `"unelevated"`（省事，代价是失去沙箱隔离），或以管理员身份把该目录所有者改回自己并授予 `FullControl`。

### 5.2 配置改动要完全重启才生效

改 `config.toml` 之后必须完全退出（含托盘图标）再启动。这也是为什么需要一个专门的「关闭 DeepSeek Codex」入口：GUI 关窗口不等于退出全部子进程。

### 5.3 PowerShell 5.1 的 BOM

Windows PowerShell 5.1 会把**没有 BOM 的 UTF-8 脚本**按 ANSI 解析，脚本里的中文会直接把语法解析坏（报 `Unexpected token`）。所以 `launcher/` 下的三个脚本都是 UTF-8 **带 BOM**。用 PowerShell 7 没这个问题，但用户双击快捷方式时走的是 5.1。

### 5.4 `-Include` 不配 `-Recurse` 不生效

想找某类文件时：

```powershell
# 找不到根目录下的文件
Get-ChildItem $HOME -File -Include *.ps1
# 正确写法之一
Get-ChildItem -Path "$HOME\*" -File -Include *.ps1
```

### 5.5 两个实例共享底层运行时

它们共用同一个 MSIX 安装目录、同一个 `%LOCALAPPDATA%\OpenAI\Codex\bin\<哈希>\codex.exe` 和 `runtimes\cua_node\<哈希>`。**客户端升级会同时影响两边**，配置里写死的哈希路径会失效。

### 5.6 会话不互通

两个 `CODEX_HOME` 的 `sessions\` 完全独立，互相看不到对方的聊天。跨环境传递信息只能靠文件。这一点直接决定了 `agent-system/` 里的协议为什么长成那样：**文件是唯一接口**。

## 6. 名词对照

| 名字 | 指什么 |
| --- | --- |
| `CODEX_HOME` | 客户端的家目录，配置、会话、技能、插件都在里面 |
| `--user-data-dir` | Chromium 层的用户数据目录，登录态与缓存 |
| `models.json` | 自定义模型目录，决定模型下拉框里有什么 |
| `AppUserModelID` | Windows 用来识别"这是哪个程序"的标识，决定任务栏图标是否合并 |
| `.sandbox-bin` | 提权沙箱用的辅助可执行文件目录 |
